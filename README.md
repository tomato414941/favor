# commission

ファンが好きなクリエイターに作品の制作を依頼するサービス。
この文脈での **commission** は、報酬を伴う作品の制作依頼を意味する。

## プロジェクト

- プロジェクト名は `commission`。正式なサービス名ではない。
- 会員向け投稿・コメント・DMを中心とする既存の `fan-site` とは別プロジェクトとして扱う。

## 仕様資料

- [基本仕様](docs/requirements.md)：基本ルール、取引の流れ、未決定事項。

## 決定事項

1. 取引の基本モデルと主要ルールは、Skebを基準にする。
2. 依頼者によるリテイク要求は禁止する。見積もり・打ち合わせ・依頼に関する自由なやり取りを前提にしない。
3. 作り手は受けたい依頼を選び、表現や仕上がりに裁量を持つ。
4. 対象を特定のジャンルや狭い用途に独自に限定せず、まずSkebの対象範囲に合わせる。
5. 作り手ごとの独自料金表・追加ルールなどを、独自仕様として追加しない。
6. 正式名称の決定は保留する。

手数料、期限、決済・返金、権利、公開範囲、対応形式などは、公式資料との照合事項として扱う。
既存の `fan-site` の会員課金や手数料設定は引き継がない。

基準資料： [Skebクライアントガイドライン](https://lp.skeb.jp/client)、[Skebクリエイターガイドライン](https://lp.skeb.jp/creator)。

## 検討中の入口：未登録クリエイターへの依頼

ファンから先に依頼を届け、クリエイターの登録につなげる方法を検討する。
これはSkeb準拠の基本方針に対する追加検討であり、採用済みの仕様ではない。
「依頼者の登録を不要にする」という案とは区別する。

### 金銭拘束を伴う案

- 送信前に、提示した依頼金額の全額についてカードの利用枠を確保する。
- 与信の有効期限内に作り手本人の確認・登録・受諾が完了したら、請求を確定する。
- 拒否・無反応・期限切れの場合は確保を解除する。
- 無期限に与信を維持したり、自動で取り直したりする前提にしない。

与信確保は一時的な金銭拘束であり、送信ごとに費用を失う仕組みではない。
単独でスパムを防げるとは考えず、次の対策を組み合わせて検討する。

- 送信件数と同時に保留できる依頼数の上限。
- 同じ相手への重複送信や、キャンセル直後の再送の制限。
- 受信者が登録せずに以後の招待を拒否できる仕組み。
- 不正なアカウントや決済手段への対策。

カード登録だけで送れる案や、無料の依頼希望だけを実需とみなす案には、スパムと支払意思の確認という課題が残る。
返金しない送信料は採用していない。

参考： [Stripeの与信確保と請求確定の分離](https://docs.stripe.com/payments/place-a-hold-on-a-payment-method)。
与信の期限や対応条件は支払方法などで異なる。この資料を参照していることは、Stripeの採用や、想定する取引方式の利用承認を意味しない。

## 未決定事項

1. 未登録の相手の指定方法、招待の届け方、作り手本人の確認方法。
2. 招待・与信・正式依頼をどう区別し、それぞれの期限をいつから数えるか。
3. 作り手が登録・受諾しなかった場合の失効、解除、再送の扱い。
4. 送信制限・受信拒否・不正利用対策の具体的な条件。
5. 想定する取引を扱える決済事業者と、本人確認・請求・返金・出金の実現条件。
6. Skeb準拠で転記すべき条件と、追加案によって差分が生じる箇所。
7. 最初の利用者をどう集め、運営・問い合わせ対応をどう担うか。

## 名称候補（保留）

名前の軸は「作り手に任せる」。以下は検討候補であり、採用や利用可能性を確認した名称ではない。

| 候補 | 意図するニュアンス |
| --- | --- |
| omakase | 作り手の腕や感性を信頼して任せる |
| Your Call | 判断・決定を作り手に委ねる |
| Surprise Me | 意外性や完成品を受け取る楽しみを期待する |
| Up to You | 作り手の自由な選択を尊重する |

公開名を決める前に、既存名称との混同、商標、ドメインなどを確認する。
