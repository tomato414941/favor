# 基本仕様

`commission` はSkebの取引モデルを基本とする創作依頼サービス。ジャンルによる分類や選択は設けず、希望する内容は依頼本文に記載する。

## 基本ルール

- 依頼者が本文と金額を提示し、作り手が受けるものを選ぶ。
- 見積もり・打ち合わせ・リテイク要求は禁止。作り手の金額設定は推奨額と最低額で、独自料金表や追加ルールは設けない。
- 承認・納品の期限は送信日から数え、承認が遅れても納期は延びない。
- 作り手自身による期限内の再納品は可能。
- **公開**：依頼者名・依頼文・作品のプレビューを公開する。
- **匿名**：依頼文・作品のプレビューは公開し、依頼者名は作り手にも知らせない。
- **非表示**：依頼文・作品をサービス内で一般公開しない。

依頼金額はいずれも第三者に非公開。非表示でも作り手によるSNS等での作品発表は制限せず、秘密保持や権利譲渡を意味しない。

基準：[クライアントガイド](https://lp.skeb.jp/client)・[クリエイターガイド](https://lp.skeb.jp/creator)。

## 取引の流れ（設計案）

依頼内容の入力 → 支払確保・送信 → 承認待ち → 承認・請求確定 → 制作 → 納品

- **カード**：送信時に利用枠を確保し、承認時に請求を確定する。
- **ポイント**：事前にチャージして使うサービス内残高。送信時に代金分を他に使えないよう確保し、承認時に差し引く。
- 承認前の取消・失効では確保を解除する。承認後の納品期限超過・ギブアップでは、支払方法に応じてカードへの返金またはポイント残高への返還を行う。
- 依頼と支払い・返金・出金の状態は分け、処理中や結果不明を完了扱いにしない。
- 権限・期限・二重処理・決済通知の遅延や失敗を検証する。キャンセル済みの依頼を通知だけで復活させない。

## 未決定事項

- 期限・入力・納品ファイルの具体的な制限。
- 決済事業者、ポイントの発行・管理方式、手数料の適用条件、本人確認、返金・出金の実現条件。
- 権利・閲覧注意設定・不正利用対策・運営対応の詳細。
- SNS認証・宛先検索の初期対応先と接続条件。体験版の固定アカウントを本番の本人確認に使わない。
- 招待の送信・再送制限の正式な数値。体験版の制限値とは区別する。

## 未登録の作り手への招待

依頼者の登録 → 宛先のSNSアカウント・本文・金額を指定 → 与信確保・招待リンク作成 → 手動で共有 → 宛先アカウントで確認 → 同意・登録・受諾 → 支払確認 → 通常の制作・納品

- 宛先はSNS提供元と固有IDに結び付ける。リンクの所持だけでは、内容の閲覧・受諾・辞退を許可しない。
- SNS側の認証結果を信頼し、こちらは宛先照合・セッション・取引権限を管理する。SNS自体の乗っ取り防止・復旧は実装範囲外。
- 内容確認や辞退・受信停止だけならユーザー登録は不要。これらにもアカウントの確認は必要。
- 招待を作成しただけでは通知済みとみなさない。相手が受け付けているDMやメールで依頼者が共有する。自動通知は行わない。
- 招待は通常の依頼と別に保存し、同意・登録・受諾時に、重複せず通常の依頼へ移行する。
- 招待の作成日時を承認・納品期限の起点とする。受諾期限は与信の有効期限を超えず、登録・受諾・リンク再発行で期限を延ばさない。
- リンク再発行で古いリンクを失効させ、取消・期限切れでは内容へのアクセスも終了する。
- 辞退・取消・期限切れでは与信確保を解除する。登録だけでは請求を確定しない。
- 送信件数・重複・再送・リンク再発行を制限する。受信者は登録せずに受信を停止・再開できる。
- 依頼者自身のSNSで共有すると、サービス内の匿名表示にかかわらず相手にSNSアカウントが伝わる。

体験版は固定のSNSアカウントと模擬カード決済で、この流れを検証する。実SNS認証や実際の与信は未接続。
与信には期限があり、それだけでスパムが防げるとは扱わない。返金しない送信料は採用していない。
与信の実現条件は要確認（[Stripeの参考資料](https://docs.stripe.com/payments/place-a-hold-on-a-payment-method)。Stripeの採用は未定）。
