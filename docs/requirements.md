# 基本仕様（草案）

`commission` はSkeb準拠の創作依頼サービス。現在は企画段階で、アプリ・決済は未実装。
以下は主要ルールと設計案の要約。ジャンルや関連機能を独自に対象外とはしない。

## 基本ルール

- 依頼者が本文と金額を提示し、作り手が受けるものを選ぶ。
- 見積もり・打ち合わせ・リテイク要求は禁止。作り手の金額設定は推奨額と最低額で、独自料金表や追加ルールは設けない。
- 承認・納品の期限は送信日から数え、承認が遅れても納期は延びない。
- 作り手自身による期限内の再納品は可能。
- 公開・匿名・非表示を区別する。匿名では作り手にも依頼者を明かさず、金額は第三者に公開しない。
- 非表示はサービス内の掲載設定であり、秘密保持や権利譲渡ではない。

基準：[クライアントガイド](https://lp.skeb.jp/client)・[クリエイターガイド](https://lp.skeb.jp/creator)。全機能・全条件の照合は未完了。

## 取引の流れ（設計案）

下書き → 支払確保・送信 → 承認待ち → 承認・請求確定 → 制作 → 納品

- カードは送信時に与信確保、承認時に請求確定。ポイントは同様にロック・差し引きを行う。
- 承認前の取消・失効は確保解除。承認後の納品期限超過・ギブアップは返金する。
- 依頼と支払い・返金・出金の状態は分ける。処理中や結果不明を完了扱いにしない。
- 権限・期限・二重処理・決済通知の遅延や失敗を検証する。キャンセル済みの依頼を通知だけで復活させない。

## 未決定事項

- 技術スタック、期限・入力・納品ファイルの具体的な制限。
- 決済事業者、手数料の適用条件、本人確認、返金・出金の実現条件。カードとポイントの返金先・条件は区別する。
- 権利・閲覧注意設定・不正利用対策・運営対応の詳細。
- 未登録クリエイターへの依頼の採否。採用時は招待方法、本人確認、正式依頼への移行と期限、送信・再送制限、受信拒否を決める。

未登録の相手には、金額分の与信確保を伴う招待を検討中。ただし与信には期限があり、それだけでスパムが防げるとは扱わない。返金しない送信料は採用していない。
与信の実現条件は要確認（[Stripeの参考資料](https://docs.stripe.com/payments/place-a-hold-on-a-payment-method)。Stripeの採用は未定）。
